# HSEVerse Terrain → meshes / ECS

Для Unity 6000.3, URP 17.3 и установленного Entities/Unity Physics. Код конвертации работает в редакторе. В клиент отправляются обычные меши, материалы, текстуры и компоненты существующих mesh/physics bakers. Новый runtime-модуль в клиенте не требуется.

## Где находится

Конвертер входит в пакет `com.hseverse.mods` (папка `Terrain`: `Runtime` — маркеры авторинга и ассет GPU-кэша, `Editor` — конвертер и bakers, `Shaders`). Отдельно его устанавливать не нужно: он есть везде, где стоит пакет, — в проекте создателя контента, в клиенте и в сборщике контента. Требуются Unity 6000.3, URP 17.3, Entities, Entities Graphics и Unity Physics. Сгенерированные ассеты записываются в проект (`Assets/HSEVerseGenerated/Terrain`), не в пакет.

Настройки рендеринга, сцены и пользовательские TerrainData в пакет не входят.

При первом экспорте компиляция вариантов шейдеров может занять дополнительное время. При повторном импорте SubScene конвертер заново обрабатывает Terrain, включая ранее сконвертированные вручную. Большое количество растительности увеличивает время обработки, расход памяти и размер контента.

## Использование

1. Откройте SubScene для редактирования. Выделите Terrain или родительский объект с несколькими Terrain.
2. Выберите **HSEverse → Terrain → Convert or Update Selected Terrains**.
3. Под исходным объектом появится `HSEVerse Converted Terrain`. Исходные Terrain и TerrainCollider сохраняются, но отключаются. Сохраните сцену.
4. Экспортируйте локацию обычным инструментом HSEVerse.

Повторный запуск обновляет результат, не добавляя вторую копию. Команда **Restore Selected Source Terrains** убирает сгенерированную иерархию и восстанавливает исходные компоненты. Обе команды поддерживают Undo. Для дальнейшего рисования Terrain сначала используйте Restore, затем снова Convert.

Меши и материалы ручной конвертации сохраняются в `Assets/HSEVerseGenerated/Terrain/Terrain*.asset`. Ручная конвертация в редакторе с видеокартой дополнительно строит GPU-кэш `Assets/HSEVerseGenerated/Terrain/<guid TerrainData>.gpu.asset`: массивы текстур слоёв, base map для дальних LOD и импостеры деревьев. Его нужно экспортировать вместе с локацией. Обновление создаёт новую версию ассета: старые версии намеренно не удаляются, чтобы Undo и другие ссылки оставались рабочими. Неиспользуемые старые версии можно удалить вручную после проверки.

## Автоматический экспорт

Нажимать Convert перед экспортом необязательно. `TerrainAutoConversion` обрабатывает временную копию сцены, которую `Unity.Scenes.Editor.SubSceneImporter` открывает в Asset Import Worker. Это тот путь, который используется `RemoteContentCatalogBuildUtility.BuildContent` экспортёра HSEVerse.

Далее обычные bakers обрабатывают созданные MeshRenderer, MeshCollider, LODGroup и префабы деревьев. Сцена на диске не сохраняется и не переписывается. Материалы и меши сериализуются вместе с entity scene. Baker зависимостей отслеживает исходные TerrainData, TerrainLayer, текстуры и префабы. Изменение данных приводит к повторному baking.

При экспорте вручную сконвертированный Terrain также пересоздаётся из сохранённого источника — старый preview не должен скрывать изменения высот/слоёв. Поэтому редактируйте источник, а не сгенерированную иерархию. Для отдельной ручной редактируемой mesh-локации этот режим не предназначен.

Автоматический путь рассчитан на сохранённые **SubScene**, включая закрытые SubScene. Он не является обработчиком обычного Build Player и не изменяет Terrain при обычном открытии сцены. В открытой SubScene для ECS-preview используйте ручную команду. Terrain, находящийся только внутри отдельного entity-prefab, не входит в этот путь обработки сцен.

## Что переносится

- Рельеф: участки по 128 × 128 ячеек, у каждого LODGroup из 4 уровней (каждый образец heightmap, каждый 2-й, 4-й, 8-й; переключение на 50 / 25 / 10 % высоты экрана, последний уровень не отсекается). По краям участков «юбки» закрывают щели между соседями на разных LOD. Совпадающие граничные вершины/нормали, UV и отверстия Terrain; вторая UV — только для lightmapped Terrain.
- Коллизия: один height-field коллайдер Unity Physics по полной heightmap (отдельный baker), с физическим материалом, слоем и include/exclude layer overrides исходного TerrainCollider. Height field не поддерживает отверстия: у Terrain с отверстиями вместо него MeshCollider по участкам с плотностью 1/4.
- Все TerrainLayer (до 16): control maps, diffuse tint, tiling/offset, normal maps/scale, metallic, smoothness, mask remap, density blending. При наличии GPU-кэша все слои рисуются за один проход из массивов текстур; слои с нулевым весом в пикселе не читаются, normal/mask массивы есть только в вариантах шейдера, которым они нужны. Дальние LOD (2 и 3) читают одну запечённую base map (цвет + нормаль, 1024²). Без кэша — прежние группы по четыре слоя с дополнительными проходами. Height blending поддержан для ≤ 4 слоёв, как в URP Terrain Lit.
- Деревья: позиции, поворот, размеры, иерархия, mesh LOD и коллайдеры префабов. Дистанции Terrain применяются к LODGroup дерева: с импостером (два перекрещенных квада, отрендеренных при ручной конвертации) последний mesh LOD переходит в импостер на billboard distance, импостер отсекается на tree distance; без импостера дерево отсекается на tree distance. Цвет экземпляра на одноматериальных URP-материалах — override `URPMaterialPropertyBaseColor` Entities Graphics (один материал на все оттенки); в остальных случаях — копии материала с оттенком, округлённым до 16 ступеней на канал.
- Размещение detail-растительности через `TerrainData.ComputeDetailInstanceTransforms`, с учётом заданной плотности Terrain. Растительность собирается по ячейкам 32 × 32 м; каждая ячейка — LODGroup, отсекаемый на detail distance Terrain (для камеры клиента 60°). Mesh-details объединяются по ячейкам и материалам; texture-grass преобразуется в перекрещенные плоскости с alpha clipping и healthy/dry tint.

Собственные шейдеры Terrain Mesh и Terrain Grass имеют DOTS-варианты и совместимы с SRP Batcher. Настройки рендер-пайплайна и рендер-ассеты проекта конвертер не изменяет.

## Границы соответствия оригиналу

- Гарантии полного пиксельного совпадения нет. Ориентир — стандартный **URP Terrain Lit**. Сторонний Terrain-шейдер заменяется стандартным смешиванием TerrainLayer с предупреждением.
- LOD рельефа выбирается по участку целиком (как у Terrain — по патчам, но без морфинга): на переходе видно смену плотности сетки. Большая heightmap/плотная растительность по-прежнему дают тяжёлый контент на диске. Без GPU-кэша материалы с > 4 слоями требуют дополнительных draw calls.
- GPU-части (массивы текстур, base map, импостеры) строит только ручная конвертация в редакторе с видеокартой. Автоматическая конвертация при импорте SubScene и сборка без видеокарты используют готовый кэш; устаревшая часть кэша (изменились слои, покраска или префаб дерева) не используется до следующей ручной конвертации — тогда рельеф рисуется прежними проходами, дальние LOD без base map, деревья без импостеров.
- Шейдеры префабов с DOTS-вариантом сохраняются. Для остальных создаются отдельные URP Lit-материалы с основной текстурой/цветом, normal map и стандартными metallic/smoothness параметрами. Об этом выводится предупреждение. Custom wind, subsurface и нестандартные packed maps при такой замене не воспроизводятся. Оригинальные материалы не изменяются.
- Terrain/SpeedTree `BillboardRenderer` заменяется последним mesh LOD (и импостером, если он построен); если mesh LOD отсутствует, конвертация сообщает об ошибке. Деревья с вложенными LODGroup оставляются как есть. Custom runtime-скрипты префабов по-прежнему ограничены возможностями существующего клиента.
- Трава статическая: плоскости не поворачиваются к камере, Terrain wind и плавное исчезновение на расстоянии не перенесены. Detail `alignToGround`, точное native healthy/dry noise и обработка нестандартных detail-материалов могут отличаться. У травы нет добавленных коллайдеров, как и у обычных Terrain details.
- Существующие lightmap index/ST копируются на рельеф. Перезапекание GI, decals, deferred depth normals при > 4 слоях, специальные режимы освещения и мобильные API требуют отдельной визуальной проверки. Источник и сконвертированный рельеф могут отличаться в этих режимах.

Ошибки в данных (пропавший tree/detail prefab, разные TerrainData у Terrain и TerrainCollider и т. п.) не должны маскироваться исчезновением объектов: конвертация сообщает об ошибке. При ошибках baking проверяйте Console/отчёт экспортёра: сам экспортёр Unity может продолжить работу после logged exception.

## Проверка

`TerrainConverterValidation.Run` — тестовый стенд для отдельного Unity-проекта. Он создаёт тестовые сцены/ассеты и временный URP asset; **не запускайте его через executeMethod в рабочем проекте с несохранёнными сценами**.

Проверяет границы участков, направление треугольников, отверстия, повторную конвертацию, raycast по ECS-коллайдерам, пять слоёв, tiling/mask remap, деревья и native detail count. Компилирует vertex/fragment стадии обычных и DOTS-вариантов на D3D, проверяет SRP Batcher. Запускает настоящий SubSceneImporter для несконвертированного Terrain и проверяет экспортированные ECS-типы, сериализованные меш/материал и неизменность исходного файла сцены.

В рабочем клиенте финально проверьте: поверхность и отверстия коллизий, normal/mask слои вблизи, деревья и их LOD/коллайдеры, траву и производительность на целевом устройстве. Это не заменяется тестом baking в редакторе.
